# ✍️ 학습 및 오답 노트

## ❌ 처음에 실수했던 부분

- **변수 초기화 미흡 (`NaN` 발생)**: `let result;` 형태로 초기화 없이 선언하여 `undefined + i` 연산 결과가 `NaN`이 됨. (`let result = 0;`으로 초기화 필요)
- **반복문 조건 범위 오류**: `i < n`으로 설정하여 n 이하인 자기 자신(n)을 포함하지 못함. (`i <= n`으로 수정 필요)
- **제곱 연산자 착오**: JavaScript에서 `^` 연산자는 제곱이 아닌 비트 XOR 연산자임. (`**` 연산자 또는 `Math.pow()` 사용 필요)
- **전역 변수 오염 위험**: `for` 문에서 `let` 없이 `for(i=1; ...)`로 작성 시 `i`가 전역 변수로 선언되는 문제. (`let i = 1` 선언 필요)

## 💡 새로 알게 된 점

- **블록 스코프(Block Scope)**: `for` 문 내부에서 `let`으로 선언한 변수는 해당 반복문 중괄호 `{ }`가 종료되면 메모리에서 자동으로 소멸되어 전역 공간을 오염시키지 않음.
- **증감식 활용 최적화**: `i++` 후 `if` 조건문으로 홀수/짝수를 가리는 대신, `i += 2` 증감식을 활용하면 필요 없는 루프 실행 횟수를 절반으로 줄일 수 있음.

## 🔍 풀이 접근법 및 성능 비교

### 1. 직관적 반복문 접근법 (O(n))

```javascript
function solution(n) {
  let result = 0;
  if (n % 2 === 1) {
    for (let i = 1; i <= n; i += 2) result += i;
  } else {
    for (let i = 2; i <= n; i += 2) result += i ** 2;
  }
  return result;
}
```

- **장점**: 의도가 명확하여 코드 가독성이 높고 유지보수가 쉬움.
- **성능**: 시간 복잡도 O(n) — n의 크기에 비례하여 연산 횟수가 증가. (현재 제한사항 n ≤ 100에서는 매우 적합)

### 2. 수학 공식을 활용한 수학적 접근법 (O(1))

```javascript
function solution2(n) {
  if (n % 2 === 1) {
    // 홀수 k개의 합: k^2 (단, k = (n + 1) / 2)
    const k = (n + 1) / 2;
    return k * k;
  } else {
    // 짝수 제곱의 합 공식: n * (n + 1) * (n + 2) / 6
    return (n * (n + 1) * (n + 2)) / 6;
  }
}
```

- **장점**: n의 크기와 상관없이 단 한 번의 연산으로 결과를 산출.
- **성능**: 시간 복잡도 O(1) — 데이터 범위가 대용량(n > 10,000,000)으로 늘어날 때 시간 초과를 방지하는 최적화 솔루션.
