# ✍️ 학습 및 오답 노트

## ❌ 처음에 실수했던 부분

- `code[i] === 1`처럼 문자와 숫자를 비교함: `code`는 문자열이라 `code[i]`는 항상 문자이므로, 숫자 `1`이 아니라 문자열 `"1"`과 비교해야 함.
- 반복문 조건을 `i <= code.length`로 설정: 마지막 순회에서 `code[length]`는 `undefined`가 되어 범위를 벗어남. (`i < code.length`로 수정 필요)
- mode와 짝수/홀수 조건을 반대로 작성함: mode가 0일 때는 짝수 인덱스, mode가 1일 때는 홀수 인덱스를 통과시켜야 하는데 반대로 구현함.
- `"EMPTY"` 체크 위치 오류: 반복문 **안에서** 매 글자마다 `ret === ''`를 검사해 조건에 안 맞는 글자를 만나자마자 바로 `"EMPTY"`를 반환해버림. 전체 문자열을 다 순회한 뒤, 최종 `ret`을 기준으로 한 번만 검사해야 함.

## 💡 새로 알게 된 점

- 배열/문자열 인덱스로 값을 비교할 때는 타입(문자열 vs 숫자)을 항상 확인해야 함 — `===`는 타입까지 엄격하게 비교하므로 `code[i] === 1`은 절대 참이 될 수 없음.
- 조건에 따라 즉시 반환(`return`)하는 로직은, "매 반복마다 확인할 것"과 "전체가 끝난 뒤 한 번만 확인할 것"을 구분해서 배치해야 함. 반복문 안에 넣으면 의도와 다르게 조기 종료될 수 있음.

## 🔍 풀이 접근법 및 성능 비교

```javascript
function solution(code) {
  let mode = 0;
  let ret = "";
  for (let i = 0; i < code.length; i++) {
    if (code[i] === "1") {
      mode = mode === 1 ? 0 : 1;
    } else if (mode === 0 && i % 2 === 0) {
      ret += code[i];
    } else if (mode === 1 && i % 2 === 1) {
      ret += code[i];
    }
  }
  return ret === "" ? "EMPTY" : ret;
}
```

- 문자열을 한 번만 순회하며 mode 전환과 조건별 추가를 동시에 처리하는 O(n) 시뮬레이션 방식.
- `"1"`을 만나면 mode만 토글하고 ret에는 추가하지 않는 것이 핵심.
- 최종 결과가 빈 문자열인지 여부는 반복이 모두 끝난 뒤 단 한 번만 판단.

## 📌 더 공부할 내용

- [ ] 반복문 내 조기 반환(early return)과 반복 종료 후 처리해야 할 로직을 구분하는 연습
