# ✍️ 학습 및 오답 노트

## ❌ 처음에 실수했던 부분

- `included[i] === "true"`처럼 boolean을 문자열과 비교함: `included`는 boolean 배열이라 실제 값은 `true`/`false`이지, 문자열 `"true"`가 아님. (`included[i] === true` 또는 `if(included[i])`로 수정 필요)
- `result`를 배열(`[]`)로 선언해놓고 숫자를 더하려고 함: 최종적으로 필요한 건 총합(숫자) 하나인데, 배열과 숫자를 혼용해서 `result += a+d`처럼 앞뒤가 안 맞는 코드가 됨. (`let result = 0;`으로 시작해야 함)
- `a+d`를 항상 고정된 값으로 더함: 등차수열은 항마다 값이 달라지는데(`a`, `a+d`, `a+2d`, `a+3d`...), `i`를 반영하지 않고 매번 똑같은 `a+d`만 더해서 항마다 다른 값을 구하지 못함. (`a + d * i` 공식으로 i번째 항 계산 필요)
- 배열을 두 개 써야 한다고 착각함: 등차수열 값을 미리 배열로 저장해뒀다가 나중에 꺼내 쓰는 방식으로 접근했는데, 각 항은 `a + d * i` 공식으로 그 자리에서 바로 계산할 수 있어 별도 배열 저장이 불필요함.

## 💡 새로 알게 된 점

- 등차수열의 (i+1)항 값은 `a + d * i` 공식으로 즉시 계산 가능 — 전체 수열을 배열로 미리 만들어둘 필요 없이, 반복문 안에서 그때그때 구하면 됨.
- 값을 한 번만 쓰고 버릴 때는 배열에 저장하기보다 그 자리에서 계산하는 게 더 간단함. 배열 저장은 값을 여러 번 재사용하거나 정렬/검색이 필요할 때 유리함.
- `reduce`는 배열을 순회하며 누적값(`acc`)을 계속 갱신해 최종적으로 값 하나로 압축하는 메서드로, `for`문에서 `let result`를 선언하고 직접 변경(mutate)하는 방식과 동일한 로직을 표현할 수 있음.

## 🔍 풀이 접근법 및 성능 비교

### 1. for문 (직관적 접근)
```javascript
function solution(a, d, included) {
    let result = 0;
    for (let i = 0; i < included.length; i++) {
        if (included[i]) {
            result += a + d * i;
        }
    }
    return result;
}
```
- 장점: 누적 변수를 직접 선언하고 조건마다 더해나가는 흐름이 명확해 이해하기 쉬움.
- 시간 복잡도 O(n).

### 2. reduce 활용 (함수형 접근)
```javascript
function solution(a, d, included) {
    return included.reduce((acc, flag, i) => {
        return flag ? acc + a + d * i : acc;
    }, 0);
}
```
- 장점: 별도의 `let` 변수 선언과 직접적인 값 변경(mutate) 없이 "배열을 값 하나로 요약한다"는 의도를 코드에 명확히 드러냄.
- for문과 동일한 O(n) 로직이지만, 누적값(`acc`)을 콜백의 반환값으로 다음 단계에 넘기는 방식이라 처음엔 for문보다 읽기 어려울 수 있음.
- 초기값(`0`), 콜백의 세 번째 인자(`i`, 인덱스)가 for문의 `i`와 정확히 대응됨.
