# ✍️ 학습 및 오답 노트

## ❌ 처음에 실수했던 부분

- `a===b===c`처럼 비교 연산자를 체이닝함: `===`는 왼쪽부터 순서대로 계산되어 `(a===b)===c`로 해석됨. `a===b`의 결과(boolean)를 다시 숫자 `c`와 비교하게 되어 의도와 전혀 다른 결과가 나옴. (`a===b && b===c`처럼 각 비교를 `&&`로 따로 연결해야 함)

- `!(a===b && b===c)`로 "두 개만 같은 경우"까지 함께 잡힐 것을 의도했으나, 이 조건은 "셋 다 같지 않은 모든 경우"(다 다름 + 두 개만 같음)를 전부 포함해버려 두 상황을 구분하지 못함. 결과적으로 else 분기가 실행될 기회가 없는 죽은 코드가 됨.

## 💡 새로 알게 된 점

- 비교 연산자는 체이닝하지 말고 `&&`/`||`로 각 비교를 개별적으로 연결해야 함.
- JS에서 거듭제곱은 `**` 연산자로 표현 (`a**2`, `a**3`).
- 조건 분기를 설계할 때, 전체 경우의 수 중 표현하기 복잡한 조건은 억지로 조건식으로 만들지 않고, 단순한 조건들을 먼저 걸러낸 뒤 나머지를 else로 처리하는 전략이 코드를 더 간결하고 실수 없게 만듦.
- `Set`을 이용하면 값들을 직접 하나하나 비교하지 않고도 "서로 다른 값이 몇 개인지"로 문제를 재구성할 수 있음 — 비교 대신 세기(counting) 관점으로 접근하는 방식.

## 🔍 풀이 접근법 및 성능 비교

### 1. if-else 직접 비교 (단순 조건부터 걸러내기)

```javascript
function solution(a, b, c) {
  if (a === b && b === c) {
    // 셋 다 같음 (단순 조건)
    return (
      (a + b + c) * (a ** 2 + b ** 2 + c ** 2) * (a ** 3 + b ** 3 + c ** 3)
    );
  } else if (a !== b && b !== c && c !== a) {
    // 셋 다 다름 (단순 조건)
    return a + b + c;
  } else {
    // 나머지 = 정확히 두 개만 같음
    return (a + b + c) * (a ** 2 + b ** 2 + c ** 2);
  }
}
```

- 세 조건이 서로 겹치지 않고 전체 경우를 정확히 나눔: 셋 다 같음 → 셋 다 다름 → (자동으로) 두 개만 같음.
- 장점: 비교 로직이 눈에 바로 보여 이해하기 쉬움.
- 시간 복잡도 O(1).

### 2. Set을 활용한 개수 세기 (비교 대신 세기)

```javascript
function solution(a, b, c) {
  const distinctCount = new Set([a, b, c]).size;
  const sum = a + b + c;
  const sumSquare = a ** 2 + b ** 2 + c ** 2;
  const sumCube = a ** 3 + b ** 3 + c ** 3;

  if (distinctCount === 3) return sum; // 다 다른 경우
  if (distinctCount === 1) return sum * sumSquare * sumCube; // 다 같은 경우
  return sum * sumSquare; // 두 개만 같은 경우
}
```

#### Set이란?

중복을 허용하지 않는 값들의 모음으로, 배열이랑 비슷한 역할을 하지만 같은 값을 여러 번 넣어도 자동으로 딱 하나만 남긴다는 점에서 결정적인 차이가 존재함.

#### 기본 사용법

```javascript
const mySet = new Set([4, 4, 4]);
console.log(mySet); // Set(1) {4}
```

[4, 4, 4]라는 배열을 넣었을 때, 중복된 4들이 자동으로 하나로 합쳐져서 Set 안에는 4가 딱 하나만 남음

```javascript
const mySet2 = new Set([5, 3, 3]);
console.log(mySet2); // Set(2) {5, 3}
```

5, 3, 3을 넣으면 3이 중복이니까 하나로 줄어서, 결과적으로 서로 다른 값 5와 3, 총 2개만 남음

```javascript
const mySet3 = new Set([2, 6, 1]);
console.log(mySet3); // Set(3) {2, 6, 1}
```

다 다른 값이면 그대로 3개 다 유지됨.

#### .size로 개수 세기

배열은 .length로 길이를 세지만, Set은 .size로 "안에 들어있는 서로 다른 값의 개수"를 셈

```javascript
new Set([4, 4, 4]).size; // 1
new Set([5, 3, 3]).size; // 2
new Set([2, 6, 1]).size; // 3
```

</details>

- `new Set([a, b, c])`가 중복을 자동 제거하므로, `.size`(서로 다른 값의 개수)만 보면 세 상황을 바로 구분 가능.
- `a===b`, `b===c` 같은 개별 비교를 직접 조합할 필요가 없어 조건 로직이 더 단순해짐.
- 시간 복잡도 O(1) (원소 3개 고정이라 Set 생성 비용도 무시 가능).
